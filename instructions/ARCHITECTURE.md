# Архитектура Blind_Log

Проект разделён по ответственности; структурная организация не должна менять поведение приложения.

## Слои

1. **GUI — `gui/`**: wxPython-окна, элементы управления, порядок фокуса и клавиатурные действия.
2. **Контроллер — `controller/`**: принимает команды GUI, координирует сервисы и журнал, возвращает результаты интерфейсу.
3. **Журнал — `journal/`**: бизнес-логика QSO, операции с записями, SQLite и черновики.
4. **Настройки — `settings/`**: значения параметров и их хранение в `settings.ini`; диалог настроек находится рядом по тематике.
5. **Интеграции — `services/` и `accessibility/`**: QRZ, обновления и уведомления NVDA.
6. **Поддерживающие модули**: `adif/` для обмена ADIF, `localization/` и `locales/` для переводов, `common/` для общих функций.
7. **Ресурсы**: `help/` для HTML-справки, `version.txt` и файлы сборки в корне.

## Правила изменений

- Не переносить бизнес-логику в GUI.
- Не менять горячие клавиши, порядок фокуса, NVDA-объявления и пользовательские сценарии без отдельной задачи.
- Сохранять коды настроек независимыми от переведённых подписей.
- Сохранять совместимость с существующими `settings.ini`, базой журнала и черновиками.
- После изменений запускать `python -m pytest tests` и проверять сборку PyInstaller.
- Старые корневые имена модулей служат совместимыми точками импорта; новая реализация находится в пакетах.

## Журнал: поиск, фильтрация и сортировка

- Отбор и сортировка отображаемых QSO реализованы в `gui/journal_filters.py`; доступный диалог и список находятся в `gui/journal_view.py`.
- Горячие клавиши подключаются в `gui/keyboard.py` через ID из `gui/ids.py`.
- Для редактирования, удаления и отметок индекс видимой строки преобразуется в индекс исходного QSO, поскольку список может быть отфильтрован и отсортирован.
- Выбранная сортировка хранится в настройке `journal_sort` в `settings.ini`.
- Проверять с NVDA порядок Tab, фокус после Enter/применения/отмены и возврат фокуса в поле при ошибке валидации.
