# Code review BlindLog

Дата ревью: 2026-06-25.

## Критические проблемы

1. **GitHub Actions падает на Windows при выводе кириллицы из Python.**
   В workflow используется `windows-latest`, а `scripts/commit_changelog.py` печатает русскоязычные сообщения. На Windows stdout может быть в `cp1252`, поэтому строка `Готово.` вызывает `UnicodeEncodeError` и останавливает релизную сборку. Исправление: принудительно включить UTF-8 для Python-процессов в workflow и перенастроить `stdout`/`stderr` в скрипте перед первым `print()`.

2. **Публикация релиза зависит от пуша в `main` из tag/workflow run.**
   `commit_changelog.py` коммитит перевод changelog и делает `git push origin HEAD:main`. При запуске по тегу `HEAD` может быть detached, а `main` мог измениться после тега. Это создаёт риск не fast-forward push или коммита в `main`, который не соответствует собираемому тегу. Исправление: либо генерировать перевод до создания тега, либо в релизном workflow использовать сгенерированный файл только как артефакт без обратного push, либо явно checkout нужной ветки и выполнять `git pull --rebase` перед пушем.

3. **Автообновление скачивает и запускает артефакт без проверки целостности/подлинности.**
   `updater.py` берёт URL из GitHub Release и устанавливает zip, но в проекте нет проверки checksum/signature. При компрометации аккаунта, release asset или сетевого окружения пользователь получает исполняемый файл без дополнительной валидации. Исправление: публиковать SHA-256/Sigstore/подпись Authenticode вместе с релизом и проверять её перед заменой exe.

## Средние проблемы

1. **Часть сетевых вызовов QRZ.ru логирует чувствительные данные косвенно.**
   `qrz_lookup.py` отправляет пароль как query parameter. Даже при HTTPS такие параметры часто попадают в proxy/server/client logs. Исправление: если API поддерживает POST — перейти на POST body; если нет — не логировать URL целиком, очищать параметры в диагностике и предупредить пользователя о риске.

2. **Версионное сравнение хрупкое.**
   `version_tuple()` ожидает только формат `X.Y.Z`. Любой префикс/суффикс вроде `v3.4.6-beta` приведёт к исключению и сломает проверку обновлений. Исправление: использовать `packaging.version.Version` или безопасный парсер с обработкой ошибок.

3. **Импорт ADIF по умолчанию сначала пробует cp1251, хотя экспорт пишет UTF-8.**
   Комментарий в `importer.py` говорит, что exporter использует cp1251, но `exporter.py` открывает файл с `encoding='utf-8'`. Для файлов с кириллицей это может дать mojibake, если cp1251 успешно декодирует UTF-8 байты как валидный текст. Исправление: синхронизировать кодировку и порядок fallback: сначала UTF-8, затем cp1251 для старых файлов.

4. **`SettingsStorage.load_config()` после ошибки cp1251 может вернуть частично пустую конфигурацию без явного Result/error.**
   Пользователь не узнает, что настройки не прочитались, а приложение продолжит работу с default-значениями. Исправление: возвращать Result или флаг ошибки, показывать понятное сообщение и/или создавать резервную копию повреждённого файла.

## Незначительные проблемы

1. **В `release.yml` есть лишние пустые строки и смешение русского/английского текста в шагах.**
   Это не ломает сборку, но усложняет поддержку. Исправление: привести стиль workflow к единому формату.

2. **В проекте встречаются широкие `except Exception` без сохранения traceback.**
   Это делает диагностику пользовательских ошибок сложнее. Исправление: использовать `logging.exception()` там, где ошибка неожиданная, и возвращать пользователю короткое сообщение.

3. **`logger.py` не настраивает handler/format сам.**
   Если вызывающий код не настроил `logging`, часть сообщений может никуда не попасть. Исправление: централизованно инициализировать file handler при включении логирования.
