# Общая информация

Проект представляет собой desktop-приложение для ведения журнала радиосвязей (QSO) радиолюбителя.

Основные цели проекта:

* удобное ведение журнала QSO
* доступность для незрячих пользователей
* поддержка NVDA
* keyboard-first интерфейс
* стабильная работа
* минимизация потери данных
* экспорт в ADIF
* поддержка обновлений приложения

Технологический стек:

* Python
* wxPython
* JSON localization
* threading
* GitHub Releases API
* QRZ.ru API
* adif-io для работы с ADIF форматом

---

# Архитектурный стиль

Проект использует слоистую архитектуру с разделением ответственности.

Основные слои:

1. UI Layer
2. Controller Layer
3. Business Logic Layer
4. Infrastructure Layer

Главная идея архитектуры:

* GUI отвечает только за интерфейс
* Controller координирует взаимодействие
* Business Layer отвечает за данные и правила
* Infrastructure Layer реализует сервисные функции

---

# Жизненный цикл приложения

Точка входа:

* main.py

Основной поток запуска:

1. Создание приложения wxPython
2. Инициализация логирования
3. Загрузка переводов
4. Создание SettingsManager
5. Проверка обновлений
6. Создание главного окна
7. Создание QSOManager
8. Создание ApplicationController
9. Восстановление temp session
10. Запуск GUI loop

При завершении:

* проверяется необходимость сохранения журнала
* выполняется экспорт при необходимости
* сохраняются временные данные

# Слои приложения

## UI Layer

Файл:

* gui.py

Назначение:

* окна
* вкладки
* меню
* кнопки
* горячие клавиши
* управление фокусом
* уведомления
* работа с NVDA
* диалоги

GUI отвечает только за отображение и взаимодействие с пользователем.

GUI не должен:

* хранить бизнес-правила
* валидировать данные QSO
* напрямую изменять данные модели

Особенности:

* keyboard-first navigation
* screen reader compatibility
* predictable focus behavior

---

## Controller Layer

Файл:

* controller.py

Назначение:

* посредник между GUI и логикой
* обработка пользовательских действий
* orchestration
* обработка ошибок
* обновление GUI
* взаимодействие с потоками

Controller:

* получает данные из GUIBridge
* формирует QSO-объекты
* вызывает QSOManager
* обновляет интерфейс
* отображает сообщения пользователю

Controller не должен:

* содержать бизнес-логику QSO
* напрямую работать с wx widgets вне GUI abstraction

---

## Business Logic Layer

Файл:

* qso_manager.py

Назначение:

* хранение списка QSO
* add/edit/delete operations
* валидация данных
* нормализация данных
* работа с temp session
* timezone handling
* QRZ lookup wrapper

QSOManager отвечает за:

* корректность данных
* consistency
* преобразование форматов
* внутренние операции с журналом

QSOManager не должен:

* показывать MessageBox
* использовать wx UI
* обновлять GUI
* зависеть от интерфейса

---

## Infrastructure Layer

Infrastructure Layer содержит сервисные модули.

---

### settings.py

Назначение:

* чтение settings.ini
* сохранение настроек
* управление настройками UI
* настройки языка
* настройки поведения приложения
* настройки видимости полей

Особенности:

* настройки должны хранить нейтральные коды
* нельзя хранить локализованный текст

Пример:

Правильно:

* utc
* custom_timezone

Неправильно:

* "UTC"
* "Задать свой часовой пояс"

---

### exporter.py

Назначение:

* экспорт журнала в ADIF формат
* генерация ADIF-заголовков
* преобразование QSO-записей в ADIF
* подготовка данных экспорта

Особенности:

* использует библиотеку `adif-io` для корректной генерации ADIF
* формирует заголовок ADIF с информацией о станции (STATION)
* экспортирует каждую QSO как отдельную запись
* поддерживает ADIF версию 3.1.7

Exporter получает:

* qso_list (список QSO из QSOManager)
* station settings (из SettingsManager)

и формирует итоговый ADIF-файл.

---

### importer.py

Назначение:

* импорт журнала из ADIF формата
* парсинг ADIF-файлов
* преобразование ADIF-записей в внутренний формат
* валидация импортируемых данных

Особенности:

* использует библиотеку `adif-io` для чтения ADIF
* преобразует ADIF-поля в поля QSOManager
* поддерживает различные версии ADIF

Importer:

* читает ADIF-файл через `adif_io.read_from_file()`
* преобразует каждую запись в словарь QSO
* возвращает список QSO для импорта

Обработка ошибок:

* валидирует корректность ADIF-файла
* логирует ошибки при парсинге

---

### updater.py

Назначение:

* проверка обновлений
* работа с GitHub Releases

* распаковка архива

Зависимости:

* settings
* constants
* i18n
* nvda_notify

Отслеживание ручного редактирования даты/времени:

* _datetime_manual_override: флаг, указывающий на ручное изменение даты/времени
* _suppress_datetime_change_events: флаг для подавления событий при программной установке
* on_datetime_control_change(): обработчик события изменения даты/времени
* _reset_datetime_override(): сброс флага при добавлении новой записи
* _set_datetime_change_suppression(): управление подавлением событий

Логика:

* При добавлении новой QSO автоматически заполняется текущее время
* Если пользователь вручную изменяет дату или время, флаг активируется
* Таймер автообновления проверяет флаг и не перезаписывает изменённые значения
* При переключении на вкладку добавления сброс флага позволяет заново автозаполнять поля

# Поток данных

## Добавление QSO

1. Пользователь вводит данные в форму
2. GUI вызывает controller.add_qso_from_gui()
3. Controller получает значения через GUIBridge
4. Формируется словарь/объект QSO
5. QSOManager выполняет:

   * validation
   * normalization
   * conversion
6. QSO сохраняется
7. Controller обновляет GUI
8. Пользователь получает уведомление

---

## Экспорт

1. Пользователь запускает экспорт
2. Exporter получает:

   * qso_list
   * settings
3. Формируется ADIF
4. Файл сохраняется на диск

---

## Импорт

1. Пользователь выбирает ADIF-файл
2. Importer читает файл
3. Выполняется парсинг записей
4. Данные преобразуются во внутренний формат
5. QSOManager выполняет валидацию
6. Записи добавляются в журнал
7. GUI обновляет отображение журнала

---

# Потоки и асинхронность

Фоновые задачи:

* QRZ lookup
* update checking

выполняются через thread.

Worker thread не должен напрямую изменять GUI.

Для возврата в UI thread используется:

* wx.CallAfter

# Доступность

Проект ориентирован на незрячих пользователей.

Критически важно сохранять:

* keyboard navigation
* tab order
* NVDA compatibility
* focus restoration
* spoken notifications
* predictable interaction flow

Нельзя:

* вводить mouse-only функциональность
* ломать keyboard workflow
* удалять уведомления без альтернативы
